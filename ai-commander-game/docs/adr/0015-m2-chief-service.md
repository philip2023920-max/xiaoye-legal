# ADR-0015 M2 技術棧：本機 Python 參謀長服務、20 秒＋事件節拍、金鑰留服務端、內建 UI、三語字串表、不串流、排與連接管
- 日期：2026-11-04
- 狀態：已採納（老闆「全照建議」，D23～D29）
- 背景：M1 的 Godot 戰鬥沙盤已能無 LLM 打完一場；M2 要把 M0 的參謀長（閘道、驗證器、準則、戰例庫、戰報卡）接進引擎，並做推翻／接管、側欄、戰後畫面、設定與費用。細節見 `docs/12-m2-architecture.md`。
- 決定：
  1. **本機 Python 參謀長服務** `chief serve`（標準庫 HTTP、JSON、127.0.0.1）；Godot 以 `OS.create_process` 啟動、`HTTPRequest` 呼叫。M0 模組一行不改重用（ADR-0011）；沙盒已實測 Godot 無頭 ↔ Python 往返。
  2. **決策節拍 20 秒＋事件**（接觸、據點易手、潰散、殲滅；與上次至少隔 8 秒）；參謀長思考時遊戲不暫停，命令回來才套用；60 秒無回覆記無回應。
  3. **金鑰留在服務端 `.env`**；設定頁只選供應商、模型、語言、預算、思考深度（存 `user://settings.json`）；加密儲存留 M3。
  4. **Godot 內建 Control**，不引 UI 外掛。
  5. **三語字串表** `godot/i18n/ui.csv` → `TranslationServer`。
  6. **不串流**：以「思考中 n 秒」指示與命令延遲標示交代；串流留 M3。
  7. **接管粒度排與連**（會戰規模）；班／旅／軍團留對應規模。
- 放棄的方案與原因：把參謀長改寫成 GDScript（兩份真相會漂，驗證器／戰例庫／戰報卡全要重做）；嵌入 Python（工具鏈脆弱）；等 AI 回來才繼續（違反 ADR-0005 即時制）；設定頁輸入金鑰（金鑰經過遊戲程序、加密要另做）。
- 後果／代價：遊戲與服務是兩個程序（要處理啟動失敗、心跳、離場清理）；M3 打包時要決定凍結 Python 的方式；推翻後果判定沿用 §9 但 M1 分區看位置，判定更即時。
