# 10 M0 模擬會戰規則 v0.1（施工單 02／03／05 的獨立事實源）

> 決策 S1（2026-11-01，老闆未反對建議答案）：5×5 分區格、每回合解算一次、簡化蘭徹斯特戰損、據點計分；10 回合或一方戰力低於 30% 結束。
> 這份文件的數字就是測試的期望值來源。改規則先改這裡，再改程式與測試。
> v0.2（2026-11-01）：依施工單 02 審查補齊程式實際行為（§2 潰散、§3 側翼細則、§4 潰散受損、§5 狀態、§7 優先序、§9 實作備註）。

## 1. 時間與規模

- 回合制，`t` 從 1 起算，最多 10 回合。
- 會戰規模（`scale: battle`）：可下令層級是連與排；排是最小行動單位（葉節點）。連是容器：戰力＝子單位平均，所在分區＝戰力最高的存活子單位所在分區。

## 2. 移動

- 每回合每個排最多移動 1 格（上下左右，不可斜走）。
- 所有地形可通行；地形只影響掩蔽度（`cover`）。
- 潰散（routed）單位：有 `withdraw` 命令就照命令走；否則每回合往最近的我方分區退 1 格，已在我方分區就不動。潰散單位不開火、不標 `engaged`，但在有敵軍的分區仍會被打（§4），戰力仍計入總戰力（§7）。

## 3. 任務式命令怎麼被編制 AI 執行

| 任務 | 對排 | 對連（拆給所有存活子排） |
|---|---|---|
| `seize X` | 朝 X 走，到達後交戰直到分區歸我方 | 同左，每個排各自走 |
| `hold X` | 在 X 原地固守；不在 X 就先走過去 | 同左 |
| `flank X` | 側翼進入點＝X 的四鄰中離「我方最強存活非潰散單位（自己除外）所在格」最遠的一格，同距依上、左、右、下順序取第一個；先走到進入點（繞路不穿過 X），再進 X | 連的第一個可行動子排（orbat 順序）原地 hold，其餘 flank |
| `withdraw X` | 朝 X 走，途中不主動交戰 | 同左 |
| `support U` | 走到友軍 U 所在分區的相鄰格並固守；已在同格或相鄰格就不動 | 同左 |
| `reserve X` | 走到 X，狀態 `idle`，不交戰除非被攻 | 同左 |

- 一個單位同一時間只有一個任務；新令覆蓋舊令。潰散或殲滅時任務清空。
- 連級命令只拆給「可行動」子排：殲滅、潰散、總司令直轄（`controlled_by: player`）的排不受影響；同一回合有自己命令的排也不受影響（排優先）。
- `controlled_by: player` 的單位：參謀長的令被驗證器退回；玩家的令照上表執行。
- 引擎自己也擋壞命令（單位不存在／殲滅、目標不是分區、support 目標不是存活友軍或是自己）：退回並寫 `info` 事件，不會寫出壞快照。

## 4. 交戰解算

同一分區同時有我方與敵方「非潰散」單位時發生交戰（相鄰格不交火）。交戰時該分區內雙方所有未殲滅單位（含潰散）都是目標。

每回合每一方對另一方造成的總傷害：

```
damage = Σ(攻方各單位 strength × fire[type]) × (1 − 守方所在分區 cover) × K
K = 0.25
fire = { infantry: 1.0, mg: 1.3, armor: 1.5, mixed: 1.2 }
```

- 傷害依守方各單位目前戰力比例分攤。沒有任何人開火的一方不會產生傷害紀錄。
- 任務為 `withdraw` 的單位不開火（含到達目標後，直到換任務），但仍會被打。
- 隨機浮動乘在「每個受害單位分攤後的份額」上（裝甲折減之後）。戰力每回合四捨五入到小數 4 位。
- 裝甲（armor）受到的傷害 × 0.6。
- 雙方同時解算（先算完兩邊再扣）。
- 隨機：`--seed` 給定時，每筆傷害乘以 0.9～1.1 的均勻亂數；`--seed` 省略或 `--no-variance` 時不乘（測試用）。

### 手算範例（測試 `test_sim.py::test_damage_hand_example` 用這組數字）

C3 城鎮（cover 0.6）：我方 `plt-A1` 步兵排戰力 0.90；敵方 `e-plt-12` 機槍排戰力 0.60。無隨機。

- 我方對敵傷害 = 0.90 × 1.0 × (1 − 0.6) × 0.25 = **0.090** → 敵 0.60 → **0.510**
- 敵方對我傷害 = 0.60 × 1.3 × (1 − 0.6) × 0.25 = **0.078** → 我 0.90 → **0.822**

## 5. 狀態轉換

| 條件 | 結果 |
|---|---|
| 戰力 < 0.30 | `routed`（潰散），寫事件 `routed` |
| 戰力 ≤ 0.05 | `destroyed`（殲滅） |
| 潰散單位退到我方分區且戰力 ≥ 0.30 | 不會回復；M0 不做整補 |
| 本回合有交戰（非潰散參戰者） | `engaged`；下一回合沒交戰就回 `idle` |
| 本回合移動但尚未到達任務目標 | `moving` |
| 本回合到達任務目標（support 以外），或沒動 | `idle` |

## 6. 分區與目標歸屬

- 回合結束時：分區內只有一方有非潰散單位 → 該方擁有，`contested=false`；兩方都有 → 原擁有者不變，`contested=true`；沒人 → 擁有者不變。
- 目標的 `owner` 跟著它所在分區。
- 分區易手寫事件 `seized`。

## 7. 結束與勝負

- 結束：任一方「總戰力」< 初始總戰力的 30%（總戰力＝所有未殲滅排戰力之和，含潰散）；或 t=10 回合解算完。兩者同時成立時 `end_reason` 記 `strength`。初始總戰力以 `Battle` 建立時的戰情板計算。
- 得分 = Σ 擁有目標的 `value`。高者勝；同分比剩餘總戰力；再同分為平手。
- 範例地圖（`samples/board_start.json` 開局；`board_t0.json` 為第 3 回合示意）目標價值：O1=3、O2=5、O3=3，滿分 11。

## 8. 敵方劇本

M0 敵方不用 AI，走 `samples/enemy_script.json`：`units` 是敵方初始部隊（與友軍 Unit 同格式），`orders` 是每回合的命令（與參謀長命令同格式）。

## 8b. 實作備註（程式有、規則沒明說的，照此為準）

- 階段：t ≤ 3 `early`、≤ 7 `mid`、其餘 `late`。
- 迷霧：可見分區＝所有未殲滅友軍排（含潰散）所在格＋四鄰。可見格內的敵軍寫入敵情，`confidence` 0.9；親眼看到被殲滅的敵軍從敵情移除；離開視野的敵情保留，`last_seen` 不變。
- 連級節點：戰力＝所有子排平均（殲滅子排以其戰力計，通常 0）；狀態：全殲滅→`destroyed`，存活者全潰散→`routed`，有交戰→`engaged`，有移動→`moving`，否則 `idle`；分區＝最強存活子排所在格（同強度取 id 順序）。
- 事件文字用繁中任務名（奪取／固守／側翼包抄／撤往／支援／預備於）。

## 9. 推翻後果判定（施工單 05 用）

推翻發生在 t，看 t+1 回合結束時被接管單位與其任務目標分區：
- 👍：單位戰力下降 < 0.05 **且**（目標分區變我方或維持我方）
- 👎：單位潰散／殲滅，或目標分區變敵方
- ➖：其他

手算例：t=3 接管 `plt-A3`（0.80）改固守 B1；t=4 結束時 0.80、B1 仍我方 → 👍。邊界：掉剛好 0.05 不算 👍（嚴格小於）。
- 「目標分區變敵方」以接管當下的擁有者為基準；support 以友軍所在格判定；單位已殲滅 → 👎。
- 推翻發生在最後一回合（沒有 t+1）→ 不判定，戰後顯示「未判定 n」。
- **推翻率（唯一定義）**＝推翻次數 ÷ 參謀長放行命令數。推翻次數＝總司令從參謀長手上接管單位的次數（改掉一條命令、或 `+` 接管一個沒命令的單位都算；已直轄單位再改令不算）；分母＝驗證器放行的命令數（退回的不算、提前結束那回合的不算）。PRD 的「第 1 場 > 40%、第 5 場 < 15%」用這個定義。接管連＝連同所有下級一起直轄，放手亦同；玩家的連令可以拆給自己直轄的排。

## 10. 驗證器規則表（施工單 03 用）

| 編號 | 規則 | 退回訊息（繁中） |
|---|---|---|
| V1 | `unit_id` 必須存在且未殲滅 | 「單位 X 不存在或已殲滅」 |
| V2 | `unit_id` 不得是 `controlled_by: player` | 「單位 X 由總司令直轄，參謀長不得下令」 |
| V3 | `task` 只能是六種之一；`seize/hold/flank/withdraw/reserve` 的 target 必須是分區；`support` 的 target 必須是友軍單位 | 「任務 T 的目標 Y 不合法」 |
| V4 | 同一回合同一單位只能有一條令（後者退回） | 「單位 X 本回合已有命令」 |
| V5 | 單一回合最多 5 條令（第 6 條起退回） | 「本回合命令超過 5 條」 |
| V6 | 潰散單位只接受 `withdraw` | 「單位 X 潰散中，只能撤退」 |

檢查順序（先中先退）：V5 → V1 → V2 → V3 → V4 → V6。連與它的排同一回合都有令是允許的：連令拆給子排時，跳過本回合有自己命令的排（排的明確命令優先，與下令順序無關）。重複下令且目標也壞的，會以 V3 退回而非 V4。
閘道層另有「寬進」正規化（不算規則）：任務同義詞（attack→seize、defend→hold、retreat→withdraw、cover→support、wait→reserve、outflank→flank）、分區 id 轉大寫、評估截 200 字、理由截 120 字。M0 不限制任務與層級的對應（任何層級都可下六種任務）。

## 11. 徽章與戰報卡（施工單 06，全部離線判定）

| 徽章 | 條件 |
|---|---|
| 果斷總司令 | 本場至少 2 次推翻的後果是 👍 |
| 放手型 | 0 次推翻且獲勝 |
| 省錢贏家 | 獲勝且本場費用 < $0.01（本地模型必然符合） |
| 守土有責 | 開局擁有的目標在戰後全部仍為我方 |

關鍵三幕：先取推翻點（最多 3），不足再依時間順序補轉折事件（`seized`／`routed`／`destroyed`）。
討論最多 3 回合（數字越界不算回合），參謀長回覆截到 2 句（中文標點一律算句尾；英文 .!? 只在後接空白＋大寫或句末時算，小數與 e.g. 不算）；準則 diff 最多新增 3、刪除 3。刪除：每條最多刪一行，先找整行相同、再找 ≥ 8 字的子字串，太短或找不到的略過並顯示。準則總長 ≤ 2,000 字，超過先淘汰最舊的待驗證假設 → 已驗證戰術 → 被否決 → 畫像（剛新增的不淘汰），仍超過才硬截。採納後 `doctrine.prev.md` 保留上一版（一層），`chief doctrine undo` 還原；`## Last adopted` 一行供下一場開局引用。自動模式只出戰報卡，不呼叫 LLM；戰後呼叫（一句話、討論、diff）全部計費，phase=aar。

## 12. 戰例庫回歸與參謀長包（施工單 07）

- **戰例**＝一次推翻：推翻當下的戰情板（上一回合快照）、參謀長原令、玩家改令、後果。每場結束自動寫入 `harness/<包>/evals/cases.jsonl`，只留最新 10 筆。
- **回歸**＝用現在的準則，把戰例裡的單位還給參謀長、重問同一局；參謀長（或其上級）對該單位下的令與玩家當時的令「任務與目標都相同」就算**對齊**。
- **成績**：對齊率＝對齊數 ÷ 戰例數；退回率＝被驗證器退回的命令 ÷ 命令總數。
- **退步**：對齊率比上一版低超過 5 個百分點。採納準則後自動回歸，退步就回滾（`doctrine undo`）並作廢該次採納；`chief evals run --doctrine samples/bad_doctrine.md` 可拿壞準則試水溫（不記成績）。
- **參謀長包**：`harness/<名稱>/`＝manifest.json、doctrine.md、prompts/chief_system.md、evals/；`chief harness export` 打包成 zip（不含金鑰、不含 .prev），`import` 驗 manifest 與路徑安全。
- **推翻率曲線**：`chief stats` 從 `battles/*/aar.json` 列出歷史戰鬥；`chief acceptance --battles 5` 連打 5 場並印曲線，M0 驗收目標是首場到末場下降。
