## PRD 符合度軸（product-manager 視角，2026-11-02）

### ① PRD 有、程式沒做或只做一半
1. F8「準則更新後用歷史快照重跑，退步就回滾」／成功定義「模擬戰果不下降超過 5%」：程式量的是「對齊率」（參謀長是否下出玩家當時的令），不是模擬戰果；第一次採納沒有基準線；每場新增戰例，前後比較的案例集不同。
   → 處置：對齊率是 M0 刻意選的代理指標（模擬戰果要等 08 的戰鬥模型才有意義），寫進 PRD 成功定義；基準線：第一次 `evals run` 記錄成績即為基準，採納前若無基準先跑一次。
2. 成功定義「同一個參謀長包在至少 3 家供應商上能完整打完一場」：M0 只能真機驗 Ollama 與 Anthropic 兩家（第三家需老闆有 OpenAI／DeepSeek 金鑰），ticket 07 未勾。→ 列為老闆真機驗收項。
3. F14「流程 2 分鐘內結束」／「中位數 < 2 分鐘；跳過率 < 30%」：`aar.json` 不記時長與跳過。→ 處置：aar.json 加 `duration_s` 與 `skipped`，`chief stats` 顯示。

明確延後（非缺陷）：F1 天氣／世代與 F15、F16 → 08；F2 20 秒節拍、側欄、F5 設定頁、F13 HUD 畫面、串流 → M2；F9 UI、F10 對決、F11 三語介面、選地圖 → M3；F12 未排程。
