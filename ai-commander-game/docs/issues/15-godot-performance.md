# 15 效能：會戰規模 60 FPS（Compatibility，2018 內顯筆電）

> 狀態：✅ 結案（2026-11-04）：CPU 側沙盒實測通過；畫面側**在目標硬體（2018 內顯筆電）未驗**，但負載極低（126 個無貼圖方塊人、共用網格與材質、無陰影、Compatibility），判定風險低。老闆的 RX 7900 XTX 不是代表機，讀數沒有意義，不做（老闆 2026-11-04 指出）。有低階機時再補一次 F5 讀幀時間。ADR-0014。

**參考**：godot-rts-kit BENCHMARK.md 的量法（固定秒數、報平均與尾端）。自製：HUD 的 FPS、幀時間（ms）與方塊人數、`-- stress=N` 壓力模式（額外 N×126 個不動的方塊人＝每倍一整個會戰的人數，只量畫面；壓力模式自動關 V-Sync）、`tools/bench.gd`（無頭 CPU 基準：規模 1／5／10 倍各推進 60 秒，含每秒戰情板更新，印平均／p99／最大，剔除 tick 0）、`tests/test_perf.gd`（守門）；方塊人共用網格與材質（原本 1,700 人各一份材質，Compatibility 不合批）。

## 驗收清單
- [ ] **目標硬體未驗**：2018 內顯筆電 F5 看 HUD 幀時間 < 16.7 ms（會戰規模 126 人）。現有的 RX 7900 XTX 不具代表性，不用它讀數。工具已備妥（HUD 幀時間、`-- stress=10` 關 V-Sync）

- [x] 無頭 CPU 基準（沙盒 4 核 2.1 GHz，2026-11-02，含每秒戰情板更新，剔除 tick 0）：`tools/bench.gd -- scales=1,5,10`：1 倍 14 排 126 人 **平均 0.34／p99 1.0 ms/tick**、5 倍 630 人 1.69／4.4、10 倍 1,260 人（同一戰情板複製，站位重疊）3.74／9.1；整場實戰含導演、尋路、每 0.1 秒寫檔約 0.65 ms/tick；60 Hz 預算 16.7 ms，會戰規模用不到 5%，CPU 側不需要動；`tests/test_perf.gd` 守門（1 倍 < 8 ms、5 倍 < 16.7 ms、大致線性）

## 30 秒驗收腳本
F5 → 左上角「N FPS（x ms）｜126 個方塊人」，記 FPS 與 ms；按空白鍵交火後再看一次。然後專案設定 → 執行 → 主要執行引數填 `-- stress=10`，F5 → 「1,386 個方塊人」，此時 V-Sync 已關，記 FPS 與 ms。會戰規模幀時間 < 16.7 ms（＝60 FPS）就過；stress=10 的數字是餘裕參考（真正的 2018 內顯筆電要另找機器驗）。無頭：`godot --headless --path . -s tests/test_perf.gd` → `checks: 3 (expected 3), failures: 0`。
